ATLAS now needs a canonical language for:

```text

fiscal periods

```

Without this layer, different Providers may return incompatible structures such as:

```text
Provider A
{
    "revenue": 60000000000,
    "netIncome": 18000000000
}

Provider B
{
    "total_revenue": "60000",
    "net_income": "18000",
    "scale": "millions"
}

Provider C
{
    "us-gaap:RevenueFromContractWithCustomerExcludingAssessedTax":
        60000000000
}
```

ATLAS modules must not depend on any of those Provider-specific formats.

The target architecture is:

```text
External Fundamental Data Source
              │
              ▼
       Provider Adapter
              │
              ▼
ATLAS Canonical Fundamental Models
              │
              ▼
        Domain Services
              │
              ├── Companies
              ├── Research
              ├── Screeners
              ├── Portfolios
              ├── Risk
              ├── AI
              ├── Agents
              └── Workflows
```

The central rule is:

# ATLAS owns the canonical Fundamental Data schema.

Provider adapters normalize external data into ATLAS models.

ATLAS does not expose Provider-specific financial-statement objects above the Provider layer.

Another critical rule is:

# Fundamental Data belongs to the canonical Company entity, not primarily to a ticker.

Use the existing Stage 18 Company identity.

Another critical rule is:

# Reported accounting facts and derived financial metrics are different things.

Stage 34 defines canonical reported fundamentals.

Stage 83 will later build:

```text
ratios
valuation metrics
derived analytics
```

Do not prematurely calculate those during Stage 34.

Another critical rule is:

# Earnings estimates, analyst forecasts and guidance are not Stage 34.

Those belong primarily to Stage 84.

Another critical rule is:

# Ownership, insider activity and institutional holdings are not Stage 34.

Those belong primarily to Stage 85.

Another critical rule is:

# Filing-document workflows are not Stage 34.

Stage 86 will connect Companies to filings/documents in depth.

Stage 34 may include safe source-document references only where the existing entity architecture already supports them.

Another critical rule is:

# Financial values must preserve exact reported precision.

Use `Decimal`.

Do not use binary floating-point for canonical accounting values.

Another critical rule is:

# Canonical financial statement values must use base units.

Do not carry hidden:

```text
thousands

millions

billions
```

scaling into canonical values.

Example:

```text
Provider:
Revenue = 1250
Scale = millions

Canonical ATLAS:
Revenue = Decimal("1250000000")
Currency = USD
```

# 93. DO NOT REJECT OPPOSITE-SIGN VALUES PURELY FROM NORMAL SIGN

# 94. CANONICAL SIGN SEMANTICS

Document a consistent economic sign convention.

Recommended:

```text

→ normally positive

expense / outflow
→ normally negative

balance-sheet balances
→ signed as economically reported
```


# 372. UPDATE DECISIONS

Append Stage 34 decisions.

At minimum record:

1. ATLAS owns canonical Fundamental Data models.
2. Provider-specific financial-statement objects must not leak above Provider adapters.
3. Fundamental reporting identity uses the canonical Company entity.
4. Ticker is not canonical Fundamental identity.
5. Security ID is not the primary Company financial-statement identity.
6. Stage 34 creates no new Company identity namespace.
7. Financial values use Decimal.
8. Binary floating-point is not canonical for financial values.
9. Non-finite financial Decimal values are rejected.
10. Canonical financial values are not globally rounded.
11. Canonical financial values are normalized to base units.
12. Thousands/millions/billions are not hidden canonical scales.
13. Missing financial values are not represented as zero.
14. Financial periods distinguish instant and duration facts.
15. Balance Sheet periods are instant.
16. Income Statement periods are duration.
17. Cash Flow Statement periods are duration.
18. Fiscal calendars are not assumed to equal calendar years.
19. Stage 34 supports annual, quarterly and other explicitly defined reporting-period types.
20. Stage 34 does not treat TTM as a normal statutory period by default.
21. Accounting standard is explicit.
22. ATLAS does not assume US GAAP globally.
23. Audit status is source/report metadata.
24. FundamentalDataOrigin captures runtime source context.
